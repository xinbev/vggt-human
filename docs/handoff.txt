# BEDLAM2 Data Handoff

## 1. Project Goal

Use the same BEDLAM2 RGB + depth sequence to train a two-stage SMPL-based model:

1. Stage 1: input SMPL parameters and depth, predict environmental scale correction.
2. Stage 2: output an SMPL sequence and optimize SMPL `trans` using depth and camera sequences.

BEDLAM2 native GT is SMPL-X locked-head. The current conversion assumes SMPL-X and SMPL translations are directly compatible. The main conversion differences are shape dimensions and detailed SMPL-X joints such as hands, face, jaw, and head.

## 9. Required Loader Pairing Logic

The next agent should build a dataset loader or manifest that joins:

```text
SMPL NPZ record
RGB PNG
Depth EXR
Depth camera/meta CSV
```

For each NPZ `imgname`, first resolve RGB using:

```text
RGB_ROOT / imgname
```

Example:

```text
imgname:
  seq_000002/seq_000002_0000.png

RGB candidate:
  /home/zhw/xyb_space/bedlam2/hf_raw/BEDLAM2/20241213_1_250_rome_tracking/png/seq_000002/seq_000002_0000.png
```

Then find the depth file with the same sequence/frame stem under `exr_depth`. Do not assume the depth extension or directory layout without checking the actual files. The loader must verify that RGB and depth frame stems match.

The first expected depth candidate is:

```text
/home/zhw/xyb_space/bedlam2/hf_raw/BEDLAM2-depth/20241213_1_250_rome_tracking/exr_depth/seq_000002/seq_000002_0000.exr
```

If this exact path does not exist, search the depth tree by stem and use `meta_exr_depth_csv` to resolve camera/frame correspondence.

The depth loader should preserve the EXR values as floating-point depth values and should not treat them as 8-bit images. It should record the depth unit/scale after inspecting the depth metadata or sample values.

## 11. Space and File Handling

The preprocessing script does not copy PNG or depth EXR files. It writes only label NPZ files to the selected output directory.

Do not delete raw RGB/depth files because the future loader needs them. After verifying the converted SMPL labels, the intermediate SMPL-X NPZ can be removed if storage is limited and no re-conversion is needed.

Do not delete motion GT or model files until all required label generation and validation are complete.
